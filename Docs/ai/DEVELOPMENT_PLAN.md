# 개발 순서

1. 현재 변경을 바탕으로 Unity 컴파일, 결정론 검색, 전체 PlayMode 기준선을 확정한다. 결과는 [HANDOVER.md](HANDOVER.md)에 남긴다.
2. 재현된 오류부터 좁게 안정화한다. Unity Console, PlayMode XML, 변경 파일을 함께 확인한다.
3. 직결 채굴 공장 작업을 이어받을 때는 기존 건설 명령, 작업자 상태 전환, 자원 노드 차감 및 귀속 규칙부터 추적한다. 건설과 배치·회수, 채굴 주기, 시설·노드 파괴 시 정리를 한 단계씩 구현하고 검증한다. 밸런스 값은 데이터 에셋에 둔다.
4. 검증된 마일스톤마다 인계 문서와 기존 README 대시보드를 갱신한다. Unity 캡처를 사용할 수 있으면 캡처를 확인해 반영한다. 게시 대상을 검토한 뒤 안정된 변경을 커밋하고 origin main과 동기화한다.

## 2026-11-20 이어서 할 작업

### 전장 사운드의 후속 검증

1. Android 스피커와 이어폰에서 다중 전투 장면의 엔진·총성과 미사일 경보를 들어 보고 채널 균형을 맞춘다.
2. 제공 음원별 출처와 배포 조건을 확보한다. 효과음의 출처를 확인할 수 없으면 확인 가능한 교체본을 검토한다.
3. 소품은 남는 맵에 맞춰 보유 Synty TrafficLight와 모바일 War FX부터 비교한다. 섬광·연막용 무료 텍스처 후보는 [구매·다운로드 목록](../ASSET-SHOPPING.md)을 참고한다.

### 조명과 HUD 검증 이후

1. 그래픽 관련 잔여 실패에서 `Visual_FilledSlotsWithinBudgetAndChecked`의 포격함부터 수정한다. 원본을 보존하고 표시용 저폴리 프리팹과 재질 슬롯 통합을 검토한다. 모바일 품질에서 4,000 삼각형·6회 그리기 예산을 다시 검사한다.
2. 물가·포격함·다중 공장 장면으로 Android 보통·높음의 프레임 시간과 화면 가독성을 측정한다. 필요 시 도로나 활주로 한 구역에서 무료 노멀 텍스처를 비교한다.
3. 두 점유 기지의 광산 검사, AI·경제 수치, 수송과 궁극기 실패를 각각 최소 경기 시나리오로 재현한다. 이후 전체 PlayMode와 온라인 경기를 검증하고 안정된 변경을 GitHub 대시보드에 반영한다.

### 조선소·채굴 작업의 후속 기록

1. 기존 PlayMode 실패를 기준선 XML과 비교해 재현 조건부터 정리하고, 이전 작업을 포함한 전체 회귀를 재실행한다.
2. Android에서 공장 관리·도크린의 터치 영역과 가독성을 확인한다. 채굴 시설을 여러 개 가동해 컨베이어와 공병 동작의 프레임 간격도 측정한다.
3. 멀티플레이에서 양 진영의 공장 증축 및 자원 채취 흐름을 확인한다. 게시 대상을 검토한 뒤 기존 GitHub 대시보드와 동기화한다.

4. 조선·활주로 적용 뒤의 전체 PlayMode는 기준선 대비 신규 실패 0건이다. 남은 기준선 실패 34건의 재현 조건을 분류한다. Android에서 조선소와 비행장을 여러 채 운용해 가독성·프레임을 확인하고, 멀티플레이에서 공병 작업과 생산 잠금 전이가 양쪽에 같은 시점에 보이는지 검증한다.
