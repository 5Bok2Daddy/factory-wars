# 기술·운영 결정

- Quantum 상태는 프레임과 컴포넌트에 두고, 고정소수점 연산과 프레임 기반 시간, `frame.RNG`, Quantum 커맨드를 사용한다. View는 경기 상태를 표시한다.
- `.qtn` 변경은 Quantum 생성 코드 및 직렬화 에셋과 함께 점검한다. 씬·프리팹·에셋의 원본 `.meta` GUID를 보존한다.
- 인수 시 미커밋 변경을 먼저 검증한다. 구입 에셋 원본과 Git 제외 대상은 로컬에 보존한다.
- 기존 GitHub 대시보드와 자동 동기화를 유지한다. 동기화 스크립트가 전체 작업 트리를 스테이징하므로 실행 전 게시 대상과 이미지 정리 대상을 점검한다. 시각 도구를 사용할 수 없는 경우에도 개발과 코드 검증을 진행한다.
- 기존 채집 노드는 목재와 철이다. Fuel은 점령 거점 종류다. 제재소 3명, 철 채굴 공장 4명으로 시작하고 인원별 배수와 생산 주기·양은 Quantum 데이터 에셋에 둔다. 공병 배치와 방출은 기존 주둔 커맨드를 재사용한다.
- 사령부로 이어지는 컨베이어와 공장 증축 부품은 Unity View에서 표시한다. 컨베이어 위 화물의 도착 연출은 Quantum의 자원 지급을 제어하지 않는다. 공장 외형과 HUD는 기존 `FactoryLevel` 및 생산 규칙을 읽는다.
- 신규 비행장·헬기장은 건설 명령이 실행될 때 인접 활주로·착륙장 부지를 예약한다. 본체 완공 뒤 기존 공병 작업을 계속하고, 부속 공사까지 끝났을 때 기존 생산 명령을 허용한다.
- 조선소는 검증된 수상 NavMesh 좌표에서 선박을 진수한다. 선체 조립과 포장 화면은 권위 있는 경기 상태에서 읽는다. 장식 바리케이드 붕괴는 확정 범위 폭발을 구독한다.
- 광원·그림자·바닥 표면·물 반사는 Unity 렌더링에서 처리한다. 보통·높음에서 바닥 굴곡과 물 반사를 켜고, 높음에는 FXAA를 적용한다. 기본 저사양 경로는 깊이 거품과 화면 공간 접촉 그림자를 끈다.
- 현장 음향은 화면 위치와 가시성에 따라 Unity View에서 섞는다. 음원 원본과 준비된 로컬 WAV는 Git 제외 경로에 보존한다. 전투 단발은 재생 간격과 채널 수를 제한하며, 엔진은 기종별 최대 한 개의 반복음으로 묶는다.
