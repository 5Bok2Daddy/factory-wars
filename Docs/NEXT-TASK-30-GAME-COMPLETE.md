## 1. 에셋 교체 준비 (그래픽 작업 대신 구조만)
사용자가 Synty 팩을 넣으면 **코드 수정 없이 데이터 연결만으로** 교체되고 바로 테스트할 수 있게 한다.
1. **비주얼 카탈로그:** 게임 요소마다 "슬롯"을 정의한다.
   - 대상: 유닛 종류별, 건물 종류별, 자원·도시 건물·지형 조각·소품·이펙트
   - 각 슬롯에 프리팹·크기·회전·피벗 보정·팀 색 적용 방식(재질 슬롯·팔레트 교체)·애니메이션 컨트롤러를 지정
   - 슬롯이 비면 지금 모델로 대체한다.
   - 데이터 에셋 하나(예: `VisualCatalog`)로 관리한다.
2. **애니메이션 연결:** 유닛 화면 코드가 이동·정지·공격·사망·건설·채집 상태를 Animator 파라미터로 보낸다(Unity 표준 인간형 기준). 애니메이션이 없는 모델도 동작한다.
3. **에셋 가져오기 도구(에디터 메뉴)**
   - temp-assets나 프로젝트의 새 팩 폴더를 읽어 프리팹 목록과 미리보기 접촉 시트를 만든다.
   - 이름 규칙으로 슬롯 후보를 자동 제안해 CSV로 내보낸다. 사용자가 고쳐서 다시 가져올 수 있게 한다.
   - URP 머티리얼 자동 변환(분홍 머티리얼 방지)
4. **교체 검증 테스트**
   - 모든 슬롯에 프리팹이 있는지
   - 모델이 판정 크기(부지·반경)를 크게 벗어나지 않는지
   - 그리기 호출·삼각형 예산
   - 선택 반경·체력바 위치가 모델 크기를 따르는지
5. **실존 무기 필터 목록:** 교체할 때 실존 무기·차량과 닮은 모델은 쓰지 않거나 변형해야 한다. 슬롯마다 "실존 유사 여부 확인" 칸을 둔다.
6. 사용 설명서 `Game/Docs/ASSET-SWAP.md`(사용자용, 쉬운 말): 팩을 넣는 위치 → 메뉴 실행 → CSV 확인 → 테스트 실행 순서.

## 2. 실제 온라인 대전 (ROADMAP 챕터 4, 28을 다시)
1. 프로젝트에 설정된 Photon **개발용 App ID**를 확인한다(PhotonServerSettings). 없거나 비어 있으면 진행할 수 있는 데까지만 하고 "막힌 것"에 적는다. 대시보드에서 새로 만들거나 설정을 바꾸지 않는다.
2. **Photon Realtime 방**
   - 6자리 코드로 방 생성·참가(방 속성에 코드)
   - 대기실: 진영·색·준비, 빈자리 비우기·봇, 난이도, 2대2, 휴전 시간, 방장 시작
   - 2명이면 대각선 자리(17B)
3. **버전 해시:** 하드코딩 문자열 대신 데이터·시뮬레이션 에셋 해시로 만든다. 입장 시 다르면 거부.
4. **Quantum 온라인 세션 시작:** 방 슬롯 ↔ PlayerRef ↔ 본진 자리. RuntimeConfig(시드·진영·색·동맹·휴전)를 방장이 확정한다.
5. **연결 끊김**
   - Quantum의 플레이어 대체 기능으로 봇이 조종한다.
   - 재접속하면 복귀한다.
   - 상대 응답이 없으면 "연결 대기"를 표시하고, 60초 후 기권 처리한다.
6. **디싱크 감지:** 개발 빌드에서 체크섬을 켜고, 디싱크가 나면 덤프를 저장한다.
7. **시험**
   - Unity Multiplayer Play Mode로 에디터 2~4개를 띄워 자동 시험한다(패키지 설치 가능, 계정·결제가 필요하면 중단).
   - 시나리오: 2인·4인, 봇 채우기, 끊김·재접속, 버전 불일치, 체크섬 일치
   - 결과·핑·입력 지연을 기록한다.
8. **사용자용 수동 시험 절차:** 폰(APK) + PC 에디터가 같은 방에서 대전하는 순서를 체크리스트로 만든다.
9. 막히는 곳(App ID, 로그인, 네트워크 차단, 패키지 설치 불가 등)은 무엇이 필요한지 정확히 적고, 오프라인으로 할 수 있는 부분을 계속한다.

## 3. 게임 완성도: "모바일 스타크래프트 + 이 게임만의 재미"
스타크래프트에서 손에 익은 조작과 흐름을 모바일에 맞게 갖추고, 처음 해 보는 사람도 한 판을 끝까지 즐길 수 있게 한다. 각 항목에 테스트를 붙인다.

### 3-1. 조작 (모바일 RTS 기본기)
- 탭 선택, 드래그 범위 선택, 더블탭으로 같은 종류 전체 선택, 길게 눌러 명령 메뉴
- 부대 지정 1~3 + 부대 버튼 탭으로 선택, 두 번 탭으로 카메라 이동
- 명령: 이동, 공격 이동(A+탭과 같은 것), 정지, 위치 고수, 순찰. 버튼과 제스처를 둘 다 지원
- 집결 지점(생산 건물 선택 후 땅 탭), 생산 대기열 5칸, 취소·환불
- 미니맵 탭·드래그로 카메라 이동, 알림을 탭하면 그 위치로
- 유휴 공병 버튼, 군대 전체 선택 버튼
- 화면 가장자리 버튼은 엄지가 닿는 위치(안전 영역, 9mm 이상). 내부 이름이 아니라 표시 이름이 보이게(예: "ff_shipyard" 금지)

### 3-2. 한 판의 흐름
- 메뉴 → AI 대전·온라인·튜토리얼 → 진영·색·난이도 선택 → 로딩 → 휴전 7분 → 전쟁 → 승리·패배 화면
- 승리·패배 화면: 통계(생산·손실·자원·점령 시간·파괴한 건물), 다시 하기, 메뉴
- 일시정지(AI 대전만), 기권
- 설정: 품질, 소리, 진동, 화면 흔들림, 카메라 속도

### 3-3. 튜토리얼 (5분 이내, 단계별)
카메라·선택 → 공병으로 채집 → 건설 → 생산 → 공격 이동·부대 지정 → 점령지 → 승리. 각 단계에 화살표와 짧은 문장. 건너뛰기 가능.

### 3-4. 재미 요소 다듬기 (이미 있는 것을 "느껴지게")
- 휴전 7분: 할 일이 보이게. 상자 회수, 빌드 목표 안내(첫 3분 추천 빌드 팁)
- 점령지·보급 투하·뒷길 바리케이드·고지대·진지·도시 붕괴·해군: 처음 나올 때 짧은 안내 말풍선 1회, 미니맵 아이콘, 알림
- 전투 체감: 유닛 사거리·상성 아이콘(누르면 "전차 → 보병에 약함" 같은 한 줄)
- 경기 템포: 2인 10~15분 목표. 늘어지면 원인 분석(소탕 지연 등)
- 외교·쪽지: 정해진 문구, 동맹 제안 알림

### 3-5. 소리 연결 구조 (소리 파일은 나중에)
- 이벤트별 소리 슬롯: 클릭, 생산 완료, 공격받음, 점령, 폭발, 붕괴, 경고. 데이터 에셋(`AudioCatalog`)으로 두고 비어 있으면 무음.
- 진동(햅틱): 공격받음, 붕괴

### 3-6. 안정성
- 20분 경기에서 메모리 증가·GC 스파이크를 측정한다.
- 앱 전환 후 복귀(일시정지·재연결)
- 오류 로그 저장
