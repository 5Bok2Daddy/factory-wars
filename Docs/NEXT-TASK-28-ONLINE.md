## 범위 (ROADMAP 챕터 4)
1. **Photon Realtime 방**
   - 6자리 방 코드 생성·참가
   - 대기실: 진영 선택, 색 선택(기존 8색), 준비, 빈자리 "비우기 / 봇 채우기"와 난이도, 2대2 동맹 프리셋(17B 규칙), 휴전 시간 선택(0·5·7·10분), 방장 시작
   - 맵은 4인 맵 하나. 2명이면 대각선 자리(17B)
2. **버전 확인:** 방 입장 시 게임·데이터 버전 해시가 다르면 안내하고 입장을 막는다.
3. **Quantum 온라인 세션:** 방의 플레이어 슬롯 ↔ PlayerRef ↔ 본진 자리를 연결한다. RuntimeConfig(시드·진영·색·동맹·휴전)는 방장이 확정한다.
4. **연결 끊김**
   - 끊긴 플레이어는 봇이 대신 조종한다(Player Replacement).
   - 재접속하면 복귀한다.
   - 상대 응답이 늦으면 "연결 대기"를 표시하고, 60초가 넘으면 기권 처리한다.
5. **디싱크 감지:** 개발 빌드에서 체크섬 검사를 켜고, 디싱크가 나면 프레임 덤프를 `Application.persistentDataPath`에 저장한다.
6. **표시:** 네트워크 상태(핑), 입력 지연 기록
7. **로그인과 닉네임:** 익명(기기 ID). 닉네임은 자동 생성 이름("지휘관 4821")만 쓰고, 자유 닉네임은 금지(애플 UGC 규정).
8. **소통:** 쪽지는 정해진 문구만, 자유 채팅 없음(이미 구현된 것 유지).

## 테스트 방법
- Unity **Multiplayer Play Mode**(패키지 관리자에서 설치. 계정·결제가 필요 없으면 설치해도 된다)로 에디터 2~4개를 띄워, 방 생성 → 참가 → 끝까지 대전을 자동 테스트로 확인한다.
- 시나리오
  - 2인(대각선)·4인 방, 봇 채우기, 2대2
  - 한 명 연결 끊기 → 봇 대체 → 재접속
  - 버전 불일치 입장 거부
  - 결정론 체크섬 일치(같은 입력 → 같은 체크섬)
- 개발 APK와 에디터가 같은 방에서 대전하는 수동 시험 절차를 체크리스트로 만든다. 사용자가 아침에 할 수 있게.

## 금지 사항 (반드시 지킴)
- Photon 대시보드 설정을 바꾸지 않는다. 특히 **무료 100 CCU 활성화 금지**. 이미 프로젝트에 설정된 **개발용 App ID만** 쓴다. App ID가 없거나 로그인이 필요하면 그 단계는 건너뛰고 보고서 "사용자가 할 일"에 적는다. 오프라인 로컬 테스트로 할 수 있는 부분은 계속한다.
- 결제·구독 변경, 비밀번호·토큰 입력, 사용자 폴더 밖 삭제, UAC를 하지 않는다.
- 네트워크를 통해 개인 정보를 보내지 않는다(익명 기기 ID만).
