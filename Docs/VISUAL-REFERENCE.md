## 구현 원칙 (성능·결정론)

- Unity 기본 Sphere·Capsule은 면이 많고 매끈해서 로우폴리 느낌이 안 나고 무겁다. **직접 만든 저면수 메쉬**(면 분할 6~12, 평면 셰이딩)를 쓴다: 상자, 경사 상자(웨지), 모서리 깎은 상자, n각 원통·원뿔대, 원뿔(드릴), 반구(돔), 회전체(냉각탑)
- 움직이지 않는 파츠는 생성할 때 하나의 메쉬로 합친다. 색·팀 컬러·발광은 팔레트 칸이고 서브메쉬는 하나다(외곽선을 켜면 둘). 움직이는 파츠(포탑, 포신, 회전익, 레이더, 크레인)만 따로 둔다
- 목표: 유닛 1기당 렌더러 2~4개, 건물 1채당 2~5개. 보병 분대는 분대 전체를 메쉬 하나로 합치고 위치 흔들림만 준다
- 팀 컬러 8색과 발광 켜짐·꺼짐은 공유 머티리얼을 바꿔 끼우는 방식 (인스턴스별 머티리얼 생성 금지, SRP Batcher 유지)
- 모든 연출은 View 코드에서만. 시뮬레이션 상태와 이벤트(정전, BarrierOpened, 사격, 채집량)를 읽기만 한다
